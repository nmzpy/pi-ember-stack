- `replace`: remove_from and remove_to take ONLY the bare 3-char hash — read row `ve7│function hello() {` means `"remove_from": "ve7"`. Never paste the line content, a code line, a paragraph, or the whole `HASH│content` row into these fields.
- `replace`: remove_from and remove_to mark the exact lines that are REMOVED, and replacement_lines is their complete replacement applied in order; nothing outside the range changes. Every line inside the range that is not reproduced byte-exact in replacement_lines is deleted from the file.
- `replace`: keep the range as tight as the change — anchor only the first and last line that actually change, never a whole function, class, or import block when only part of it changes.
- `replace`: to replace a single line, set both remove_from and remove_to to the same hash: remove_from: "<HASH>", remove_to: "<HASH>".
- `replace`: replacement_lines must NEVER contain a HASH│ prefix — pass bare content only. When copying a line from read output, strip the `HASH│` prefix and keep the leading whitespace exactly as shown. A pasted `HASH│` prefix is auto-stripped, but a near-miss prefix (wrong hash length) can leak a literal `│` into the file, so always send bare lines.
- `replace`: replacement_lines is an array of strings, one element per line. Mirror the removed lines exactly, blank lines included: use `[]` to delete the range, `[""]` for a single blank line, `["a", ""]` for a line followed by a blank line, and `["", ""]` for two blank lines. Do not embed `\n` inside an element — each element is exactly one line.
- `replace`: the result confirms success in one line — `Added N line(s), removed M line(s). Lines X–Y changed.` — that range plus the removed-line count verifies the edit hit the intended lines. Hashes shift after any edit, so do NOT reuse pre-edit anchors for a follow-up edit: call read with offset/limit to get fresh anchors for the range you need next. (When auto-read is enabled, the result also includes a delta diff of only the changed rows; `+HASH│` rows are then the fresh anchors.)
- `replace`: for a large contiguous deletion (removing a whole function, test block, or section of 50+ lines where you have NOT read every interior line), set `endpoint_only: true`. This trusts just the two endpoint hashes and skips the interior stale check — the default check rejects large deletes as stale when interior lines were never shown. The endpoints are still validated for existence and uniqueness. Use `endpoint_only` ONLY for large block deletions; for small surgical edits where you have seen the full range, leave it unset so the interior check catches real drift.
- `replace`: if you hit `[E_RANGE_STALE]`, the error gives the two fresh endpoint hashes and a retry hint — either re-read the range for fresh interior anchors, or set `endpoint_only: true` on the retry to trust just the endpoints. Do NOT drop to bash sed for large deletions; endpoint_only keeps you in the safe tool.
- `replace`: do not issue multiple replace calls on the same file in one message. Issue the next edit only after verifying the previous diff.
