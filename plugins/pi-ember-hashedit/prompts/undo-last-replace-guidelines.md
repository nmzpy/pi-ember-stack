- `undo_last_replace`: reverts only the most recent replace on the file — any write to the file clears the undo history, so call it immediately after a bad replace. A replace is bad when the confirmation's `Lines X–Y changed` / removed-line count disagrees with your intent (it hit a closing brace, import, or declaration you meant to keep).
- `undo_last_replace`: the confirmation states the file is reverted and how many lines were restored/removed. Hashes shift on undo, so call read to get fresh anchors before further edits.
